# 3주차 이론 정리: 셸 스크립팅 및 가상화 기초

## 1. 셸 스크립트(Shell Script)와 자동화

### 1) 자동화의 필요성
- **반복 작업의 효율화**: 일일 로그 분석, 백업, 오래된 파일 정리와 같이 주기적으로 반복되는 작업을 자동화하여 작업 시간을 대폭 단축.
- **휴먼 에러(Human Error) 방지**: 사람이 직접 명령어를 입력할 때 발생할 수 있는 오타, 명령 수행 순서 착오, 절차 누락 등의 실수를 방지하고 일관된 동작을 보장.

## 2. 셸 스크립트 핵심 구성 요소 및 문법 원리

### 1) 셔뱅 (Shebang - `#!`)
- **개념**: 스크립트 파일의 첫 번째 줄에 작성되는 문자로, 해당 스크립트를 해석하고 실행할 **인터프리터(Interpreter)의 경로**를 시스템(OS)에 지정.
- **작동 원리**:
  - `#!/bin/bash`: 스크립트를 Bash 셸 인터프리터로 실행.
  - `#!/usr/bin/env python3`: 시스템 PATH 환경변수에서 `python3`을 찾아 실행.
- **주의**: `#` 뒤에 `!`가 붙지 않으면 일반 주석으로 처리됨.

### 2) 실행 권한 및 경로 지정
- **권한 관리**: 기본적으로 생성된 스크립트 파일은 실행 권한(`x`)이 없으므로 `Permission denied` 오류가 발생. `chmod u+x <파일명>`으로 실행 권한을 부여해야 함.
- **상대 경로 실행 (`./`)**: 보안상의 이유로 현재 디렉터리가 기본 `PATH` 환경변수에 포함되어 있지 않으므로, 스크립트 실행 시 `./start.sh`와 같이 경로를 명시해야 함 (`Command not found` 방지).

### 3) 경로 고정 패턴 (`cd "$(dirname "$0")"`)
- 외부 디렉터리에서 스크립트를 호출하더라도 파일 위치 기준으로 작업 경로를 고정하기 위한 구문.
  - `$0`: 실행된 스크립트 자신의 파일 경로/이름.
  - `dirname`: 파일 경로에서 파일 이름을 제외한 디렉터리 경로만 추출하는 명령어.
  - `$(...)` (**명령어 치환, Command Substitution**): 괄호 안의 명령어 실행 결과를 해당 위치의 문자열로 대체.

### 4) 논리 연산자와 종료 상태 (Exit Status)
- 리눅스 명령어는 실행 후 성공 여부를 **종료 상태 코드(Exit Code)**로 반환.
  - `0`: 성공 (True 의미)
  - `0 이외의 숫자` (예: `1`): 실패 (False 의미)
- **Short-circuit Evaluation (단락 평가)**:
  - `A || B`: **논리 OR 연산자**. A가 실패(`exit status != 0`)할 때만 B를 실행. (예: `cd ... || exit 1` ➔ 디렉터리 이동 실패 시 스크립트 종료)
  - `A && B`: **논리 AND 연산자**. A가 성공(`exit status == 0`)할 때만 B를 실행.

### 5) `exec` 명령어
- 현재 실행 중인 셸(Bash) 프로세스를 종료하고, 지정한 새로운 프로그램 프로세스로 완전히 대체(Process Replacement).
- **특징**: 새로운 자식 프로세스를 생성하지 않고 기존 프로세스 ID(PID)를 유지하여 시스템 리소스를 절약.

### 6) 입출력 리다이렉션 (Redirection)과 파일 기술자 (File Descriptor)
- **표준 스트림 종류**:
  - `0`: 표준 입력 (`stdin`)
  - `1`: 표준 출력 (`stdout`)
  - `2`: 표준 에러 (`stderr`)
- **리다이렉션 기호**:
  - `>`: 표준 출력을 다른 곳(파일 등)으로 보냄 (덮어쓰기).
  - `>>`: 표준 출력을 파일 끝에 추가 (이어쓰기).
  - `>/dev/null`: 출력을 쓰레기통 장치로 보내 화면에 표시되지 않도록 버림.
  - `2>&1`: 표준 에러(2)를 표준 출력(1)이 나가는 방향과 동일한 곳으로 전달.
  - `>&2`: 메시지를 표준 에러(stderr) 스트림으로 출력.

## 3. 대형 언어 모델(LLM)과 로컬 AI 서비스 개념

### 1) 파라미터(Parameter)와 모델 크기 (`b`)
- **`b` (Billion)**: 10억 개를 의미하며, 모델이 학습한 매개변수(파라미터)의 총개수를 뜻함 (뇌의 신경망 크기에 비유).
  - 예: `0.6b` = 약 6억 개의 파라미터.
- **특징**:
  - 파라미터 수가 클수록 언어 패턴 표현력이 뛰어나고 높은 응답 품질을 제공함.
  - 대신 연산량이 커지므로 더 높은 컴퓨팅 자원(CPU, GPU, RAM)과 메모리 용량이 필요하며 응답 속도가 느려질 수 있음.

### 2) Ollama 플랫폼
- 로컬 환경에서 오픈소스 LLM(Qwen, Llama 등)을 복잡한 환경 설정 없이 쉽게 다운로드, 실행, 관리할 수 있도록 지원하는 프레임워크.
- 백그라운드에서 API 서버(기본 포트 `11434`) 형태로 작동하며, HTTP REST API를 통해 외부 애플리케이션과 통신함.
