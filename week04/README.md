# 4주차: 자동화와 협업, 그리고 네트워크 기초

## 1. 개요 및 학습 목표
- 셸 스크립트 기반의 반복 작업 자동화 및 경로 제어 체계 습득
- 프로그램과 프로세스의 차이 이해 및 프로세스 상태 관리/제어
- Git/GitHub 브랜치 전략, Pull Request(PR), Conflict 해결을 통한 협업 흐름 파악
- IP 주소, 포트(Port), DNS 등 네트워크 기초 개념 이해 및 관련 CLI 도구 활용

---

## 2. 주요 학습 내용 정리

### 1) 자동화 기초 및 검색 명령어
- **경로 체계**:
  - **절대 경로**: 루트(`/`)부터 시작하는 전체 경로
  - **상대 경로**: 현재 작업 디렉터리(`.`) 또는 상위 디렉터리(`..`) 기준 경로
  - **`cd "$(dirname "$0")"`**: 스크립트 실행 위치에 관계없이 스크립트가 존재하는 디렉터리를 기준으로 동작하도록 보장
- **핵심 리눅스 디렉터리 구조**:
  - `/`: 루트 디렉터리
  - `/home` (`~`): 사용자 홈 디렉터리
  - `/etc`: 시스템 및 서비스 전역 설정 파일 위치
  - `/var/log`: 시스템 및 애플리케이션 로그 저장 위치
- **검색 및 텍스트 처리 도구**:
  - `find`: 디렉터리 트리를 탐색하여 조건에 맞는 파일/디렉터리 검색 (`-type f`, `-name` 등)
  - `grep`: 텍스트 내에서 특정 패턴을 검색 (`-R`: 하위 디렉터리 재귀 검색, `-n`: 줄 번호 표시, `-i`: 대소문자 무시, `-v`: 패턴 제외)
  - `pipe (|)`: 앞 명령어의 표준 출력(stdout)을 뒤 명령어의 표준 입력(stdin)으로 연결
  - `wc -l`: 입력된 텍스트의 전체 줄 수 계산

### 2) 프로세스 제어 및 백업 자동화
- **프로그램 vs 프로세스**:
  - **프로그램 (Program)**: 디스크에 저장된 실행 가능한 바이너리 또는 코드 파일
  - **프로세스 (Process)**: 메모리에 로드되어 실제 실행 중인 프로그램 (PID로 식별)
- **프로세스 조회 및 제어**:
  - `ps aux`: 시스템에서 실행 중인 전체 프로세스 상태 출력
  - `htop`: 실시간 프로세스 및 시스템 리소스 모니터링 도구
  - **시그널 (Signal)**:
    - `SIGTERM (15)`: 정상 종료 요청 (프로세스가 정리 작업을 진행 후 종료)
    - `SIGKILL (9)`: 강제 종료 (최후의 수단, 즉시 프로세스 제거)
    - `SIGINT (2)`: 인터럽트 요청 (`Ctrl + C`)
- **아카이빙 및 파일 비교**:
  - `tar`: 파일들을 아카이브로 묶거나 압축 (`-czf`: gzip 압축 생성, `-xzf`: 압축 해제, `-tzf`: 내용 목록 확인)
  - `diff -rq`: 두 디렉터리/파일 간 차이점 유무를 비교 및 검증 (반환 코드 `0`: 동일, `1`: 다름)
- **버전 관리 제외 (`.gitignore`)**:
  - 자동 생성되는 로그, 백업 파일, 빌드 결과물 등 추적 불필요한 대상을 Git 관리 목록에서 제외

### 3) Git/GitHub 기반 협업 및 충돌(Conflict) 해결
- **브랜치(Branch) 전략**:
  - 기준 브랜치(`main`)와 독립된 작업 공간(`feature/기능명`, `fix/버그명` 등)을 분리하여 안전한 개발 진행
- **Pull Request (PR) 및 병합 (Merge)**:
  - `gh pr create`: CLI 환경에서 변경 사항에 대한 코드 리뷰 및 병합 요청 제출
  - **Squash Merge**: PR에 포함된 여러 개의 커밋 이력을 하나로 단일화하여 `main` 브랜치에 병합
- **충돌(Conflict) 원인 및 해결**:
  - **충돌 발생 원인**: 공통 조상(Base)을 기준으로 서로 다른 브랜치에서 동일한 파일의 같은 위치를 다르게 수정한 경우 발생
  - **충돌 해결**: Git 충돌 표기 구문(`<<<<<<<`, `=======`, `>>>>>>>`)을 확인하고 사용자가 남길 최종 코드를 수동 결정 후 커밋/푸시

### 4) 네트워크 기초 및 웹 서버 상태 점검
- **식별 체계 (IP & Port)**:
  - **IP 주소**: 네트워크상에서 컴퓨터/장치를 식별하는 주소 (공인 IP vs 사설 IP, `127.0.0.1`/`localhost`: 자기 자신)
  - **NAT (Network Address Translation)**: 내부 사설 IP를 공인 IP로 변환하여 외부 인터넷과 통신하게 하는 기술
  - **포트 (Port)**: 한 장치 내에서 실행 중인 특정 네트워크 서비스/프로세스를 구분하는 번호 (예: SSH-22, HTTP-80, HTTPS-443)
  - `0.0.0.0`: 서버의 모든 IPv4 네트워크 인터페이스에서 연결 요청을 수신(Bind)하겠다는 의미
- **도메인 이름 시스템 (DNS)**:
  - 문자로 된 도메인 이름을 컴퓨터가 인식할 수 있는 IP 주소로 상호 변환 (`dig`, `nslookup` 명령어로 조회)
- **네트워크 진단 및 HTTP 통신 도구**:
  - `ping`: ICMP 응답을 통한 네트워크 도달 가능성 점검
  - `curl`: HTTP/HTTPS 요청 전송 및 응답 확인 (`-I`: 헤더만 확인, `-s`: 진행률 숨김)
  - `jq`: JSON 형식을 파싱 및 처리하는 CLI 도구
  - `ss -tlnp`: 현재 대기(LISTEN) 상태인 TCP 포트 및 해당 프로세스(PID) 조회
- **포트 충돌 (Address already in use)**:
  - 동일한 포트 번호를 이미 다른 프로세스가 점유 중일 때 발생하며, 포트 번호를 변경하거나 점유 중인 프로세스(`kill`/`pkill`)를 종료하여 해결

## 3. 수행 내용 요약
- **자동화 스크립트 구현**: `find`, `grep`, `pipe`를 조합한 조건별 파일 탐색 및 `tar`, `date`, `$$`(PID)를 활용한 타임스탬프 기반 백업 스크립트 작성
- **Git/GitHub 협업 실습**: `feature` 브랜치 생성, 커밋, PR 작성, 의도적 충돌 유발 후 충돌 표기 구문 수동 해소 및 병합 완료
- **로컬 웹 서버 구축 및 네트워크 진단**: Python 모듈(`python3 -m http.server`) 기반 웹 서버 구동, `curl` 및 `ss` 명령을 통한 응답 코드/포트 바인딩 상태 확인, 포트 충돌 상황 해결
